这周把整站换成了像素风：Zpix 中文像素字体、NES 配色、马里奥的精灵图，页头 Logo 换成了奇诺比奥，页面底部加了一条会跑马里奥的地面。

看起来只是换套 CSS，实际上牵出一串问题。挑六个值得记的说。

## 坑一：白底白字，自己看不见

主题里有两个变量：

```css
--surface: #ffffff;  /* 卡片、按钮的底色 */
--fg:      #ffffff;  /* 正文颜色 */
```

卡片是白的，字也是白的，对比度 **1:1**。所有按钮、设置卡、游戏卡、输入框全部隐形。

更坑的是我一开始没发现——因为 `@media (prefers-color-scheme: dark)` 里 `--surface` 是深色，深色模式下一切正常。**只在浅色模式坏**。

修改就一行：正文改成深棕 `#24150a`。顺手算了下对比度，从 1.0 提到 17.4。

> 教训：给「表面色」和「文字色」分别命名，不要让一个 `--fg` 同时负责两种背景上的文字。

## 坑二：只有首页变了样

改完 `global.css` 和首页，我以为完工了。打开「吃什么」一看，还是圆角卡片、1px 细边框、柔和阴影——和首页完全是两套设计。

数了一下：四个子页面里 **53 处圆角、33 处 1px 边框**。它们各自写了自己的样式，从来没引用过全局变量。

最后用脚本批量替换：`border-radius` 一律归零，`border: 1px` 提到 3px。一次改完才算统一。

> 教训：主题化不是改一个文件，是改「所有没引用变量、写死样式」的地方。

## 坑三：同步的密钥，每次构建都会丢

多端同步用到了一个口令哈希和一个签名密钥。按老习惯，我在 Cloudflare 面板的「变量和机密」里填了。

结果每次推代码重新部署后，接口就报「同步未配置」。

原因：**用 Git 构建的 Worker，以仓库里的 `wrangler.jsonc` 为准**。面板里加的是「版本级」配置，新构建生成新版本时就被覆盖了。面板甚至自己弹了黄条提示：

> 更新您的 Wrangler 配置以应用这些更改，确保部署保持同步。

最后的解法不是把密钥塞进仓库（那等于公开），而是**搬进 D1 数据库**：口令哈希存一行记录，签名密钥由 Worker 首次运行时自动生成。

```sql
INSERT INTO meta (k, v) VALUES ('passphrase_hash', '...')
ON CONFLICT(k) DO UPDATE SET v = excluded.v;
```

一次配置，之后重建多少次都不会丢。

> 教训：把「会变的基础设施配置」和「构建产物」分开。数据库能活过构建，环境变量不一定。

## 坑四：新设备一同步就报错

在另一台设备上点同步，弹出一行英文：

> Failed to execute 'transaction' on 'IDBDatabase': One of the specified object stores was not found.

原因很直接：那台设备没存过照片和书，`yakult-eat`、`yakult-read` 两个 IndexedDB 库根本不存在，代码却直接去 `transaction('images')`。

改成先探测：库存不存在、表存不存在，都没有就跳过。记录照常同步，图片和书等有数据了再传。

顺带发现旧代码还可能在设备上**误建空库**（有库没有表），于是把两个库的版本号都升了一级，在 `onupgradeneeded` 里补齐缺失的表。

> 教训：本地存储不是「一定存在」，读之前先确认。

## 坑五：抓数据比写页面难得多

给 150 道内置菜谱配图，本想从菜谱站抓。过程比预想的曲折：

- **按 User-Agent 过滤**：完整的 Chrome UA 连首页都返回 404，换个简化版 UA 就正常
- **搜索接口限流**：前 6 次正常，第 7 次开始返回空数组（不是 403，是「查无结果」，很容易误判成没这本书）
- **图片防盗链**：不带 `Referer` 返回 **418**，加上 `Referer: https://book.douban.com/` 就是 200

最后豆瓣的书改用它的搜索建议接口 `/j/subject_suggest`，稳定且字段更全；图片统一压到 480×360、质量 78，150 张一共 5 MB。

> 教训：动手前先用几条数据试通，再批量跑。失败要能区分「真没有」和「被拦了」。

## 坑六：GIF 的背景不是透明的

底部跑动马里奥用的是一个 16×29、4 帧的 GIF，我很喜欢这个动作，但它的背景是纯色 `rgb(4,0,0)`，不是透明——放在棕色地面上就是一块黑方块。

抠法很简单：逐帧把该颜色像素的 alpha 设为 0，收拢出 16 色调色板，重新导出带透明索引的 GIF。四帧、每帧 120ms、循环播放都保持不变。

唯一要注意的是**别把精灵自己的深色描边一起抠掉**。这个 GIF 的背景是 `(4,0,0)`，描边是纯黑 `(0,0,0)`，颜色不同才能安全区分。

> 教训：像素画的「背景」往往是一个具体颜色，不是 alpha 通道。抠之前先看调色板。

## 一点总结

改个主题听起来是审美问题，实际踩到的全是工程问题：命名、样式作用域、构建与配置的关系、本地存储的边界、外部数据源的脾气。

如果重来一次，我会先做两件事：**先把颜色对比度算一遍**，**先在一个子页面跑通再铺开**。能省掉大半返工。
